모바일 PWA 기준으로 잡는 게 제일 맞다. 핵심은 **현장에서 QR 스캔 → 2~3번 터치로 등록/이동/장착**이 끝나도록 하는 것이다.

## 1. 모바일 홈

```text
┌──────────────────────────┐
│ Inventory                │
│                    홍길동 │
├──────────────────────────┤
│                          │
│      ┌────────────┐      │
│      │            │      │
│      │  QR 스캔   │      │
│      │            │      │
│      └────────────┘      │
│                          │
├──────────────────────────┤
│ [ 자산 검색 ]            │
│                          │
│ [ 재고 현황 ]            │
│                          │
│ [ 재고 조사 ]            │
│                          │
│ [ 최근 작업 ]            │
├──────────────────────────┤
│ 홈     검색     재고     │
└──────────────────────────┘
```

QR 스캔 버튼을 가장 크게 둔다.

---

## 2. QR 스캔 화면

앱 내부에서 카메라 스캔을 하는 경우다.

```text
┌──────────────────────────┐
│ ← QR 스캔                │
├──────────────────────────┤
│                          │
│                          │
│     ┌──────────────┐     │
│     │              │     │
│     │   QR CODE    │     │
│     │   SCANNER    │     │
│     │              │     │
│     └──────────────┘     │
│                          │
│ QR 코드를 화면 안에      │
│ 위치시켜 주세요.         │
│                          │
├──────────────────────────┤
│ [ Asset ID 직접 입력 ]   │
└──────────────────────────┘
```

다만 QR 자체가

```text
https://inventory.example.com/a/ASSET-000042
```

형태라면 휴대폰 기본 카메라로 바로 접근할 수도 있다.

# 3. 미등록 자산 화면

이 화면이 가장 중요하다.

최대한 단순하게 만든다.

```text
┌──────────────────────────┐
│ 새 자산 등록             │
├──────────────────────────┤
│                          │
│ ASSET-000042             │
│                          │
│ 아직 등록되지 않은       │
│ 자산입니다.              │
│                          │
│ 자산 종류 *              │
│ ┌──────────────────────┐ │
│ │ SSD                ▼ │ │
│ └──────────────────────┘ │
│                          │
│ 현재 위치 *              │
│                          │
│ ┌─────────┐ ┌─────────┐ │
│ │   IDC   │ │ Office  │ │
│ └─────────┘ └─────────┘ │
│                          │
│                          │
│ ┌──────────────────────┐ │
│ │       등록하기       │ │
│ └──────────────────────┘ │
│                          │
│ 상세정보는 나중에        │
│ 추가할 수 있습니다.      │
└──────────────────────────┘
```

사용자가 입력해야 하는 건 사실상:

```text
SSD 선택
+
IDC 선택
+
등록
```

끝이다.

# 4. 자산 종류 선택

자산 종류가 몇 개 안 되므로 드롭다운보다 버튼 UI도 좋다.

```text
┌──────────────────────────┐
│ 자산 종류 선택           │
├──────────────────────────┤
│                          │
│ [ SSD ]      [ HDD ]     │
│                          │
│ [ RAM ]      [ NIC ]     │
│                          │
│ [ GPU ]      [ PSU ]     │
│                          │
│ [ HBA/RAID ] [ 기타 ]    │
│                          │
└──────────────────────────┘
```

현장 등록 속도만 보면 이 방식이 더 빠르다.

반복할 수 있어야 한다.

## 메뉴 구조도

전체 UI는 이 정도로 단순하게 잡으면 된다.

```text
Inventory
│
├─ 홈
│   └─ QR 스캔
│
├─ 자산
│   ├─ 검색
│   ├─ 상세
│   ├─ 정보 수정
│   ├─ 이동
│   ├─ 장착/탈착
│   └─ 이력
│
├─ 재고
│   ├─ 전체
│   ├─ IDC
│   └─ Office
│
├─ 재고 조사
│
└─ 관리자
    ├─ QR 발급
    ├─ 위치 관리
    ├─ 사용자/권한
    └─ Audit Log
```

가장 중요한 UX 원칙은 **`QR 스캔 → 화면 하나 → 작업 완료`**다. 등록하면서 제조사·모델·용량·Serial·Rack까지 전부 물어보는 순간 현장에서는 안 쓰게 될 가능성이 높다.

이 설계라면 최초 등록은 실제로 **`QR → SSD → IDC → 등록` 4단계**면 끝난다.
